# Autonomous Forensic Memory for PACS

## Overview

**Autonomous Forensic Memory for PACS** is a research prototype for automated forensic incident detection and evidence preservation in Picture Archiving and Communication System (PACS) environments.

The system simulates PACS security events, detects suspicious activity, stores forensic evidence in persistent memory, builds an incident timeline, verifies evidence integrity using SHA-256 hash chaining, and generates an automated forensic incident report.

## Key Features

* 🏥 PACS security-event simulation
* 🔐 Detection of suspicious authentication activity
* 🩻 DICOM access and modification monitoring
* 🗄️ PACS database activity monitoring
* 🌐 Network anomaly detection
* 🧠 Persistent forensic memory using SQLite
* 🕒 Automated incident timeline generation
* 🔗 SHA-256 hash chaining for evidence integrity
* ✅ Evidence integrity verification
* 📋 Automated forensic report generation
* 🌐 Interactive Streamlit dashboard

## Installation

Clone the repository:

```bash
git clone https://github.com/mpnaveen3004bme-sudo/autonomous-forensic-memory-pacs.git
cd autonomous-forensic-memory-pacs
```

Install the required Python packages:

```bash
python -m pip install -r requirements.txt
```

If Windows does not recognize the `streamlit` command directly, use:

```bash
python -m streamlit run app.py
```

## Running the Application

Start the Streamlit dashboard:

```bash
python -m streamlit run app.py
```

The application will be available locally at:

```text
http://localhost:8501
```

## Demonstration Workflow

1. Start the Streamlit application.
2. Generate a new PACS incident.
3. Review the detected incident and event statistics.
4. Examine the incident timeline.
5. Review the stored forensic evidence.
6. Run **Verify Evidence Integrity**.
7. Confirm that integrity verification passes.
8. Generate the forensic report.
9. Download or inspect `forensic_report.txt`.

## Example Incident

The prototype can generate a suspicious PACS activity sequence containing:

* Multiple failed PACS login attempts
* A successful login
* Unusual DICOM image access
* DICOM metadata modification
* Unexpected PACS database modification
* Unusual network activity

These events are combined into an incident timeline and preserved as forensic evidence.

## Evidence Integrity

The prototype uses **SHA-256 hash chaining** to protect the integrity of stored forensic evidence.

During testing, the application successfully reported:

```text
Evidence protected using SHA-256 hash chaining.
Integrity verification: PASSED
```

This provides an integrity-checking mechanism for the evidence generated by the prototype.

## Forensic Report

The system generates an automated forensic incident report containing:

* Incident status
* Evidence-event count
* Failed login count
* Suspicious-event count
* Incident timeline
* Forensic evidence details
* Evidence integrity status

The generated report is stored as:

```text
forensic_report.txt
```

## Research Scope

This project is a **research prototype** intended to demonstrate concepts related to autonomous forensic memory and incident analysis in PACS environments.

It is not intended to replace:

* Production PACS security controls
* Clinical information systems
* Enterprise security monitoring
* Formal digital-forensics procedures

## Limitations

* The PACS events are simulated for research and demonstration purposes.
* The prototype is intended for local experimentation.
* The system does not represent a production hospital security infrastructure.
* Detection logic is based on the simulated event patterns implemented in the prototype.
